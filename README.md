# Project Zomboid Server Admin Scripts

Automated maintenance, supply drops, and mod management scripts for self-hosted [Project Zomboid](https://github.com/indifferentbroccoli/projectzomboid-server-docker) Docker servers. 

Designed for low-overhead server administration without relying on third-party panel tools. Originally built for the PaymoneyWubby Discord server.

---

## Core Scripts

### Caretaking (`caretaking.sh`)
Automated reboot logic that checks player activity before initiating server updates. Designed to run as an hourly cron job.

* **Smart Player Detection:** Checks online player counts via RCON before taking action.
* **Dynamic Warning System:** Issues an RCON `servermsg` warning players to find safety (30–90 second delay).
* **Load-Aware Delays:** Extends warning times during configurable prime-time hours to account for high server traffic.
* **Graceful Restarts:** Triggers an RCON `save` and `quit`. Relies on Docker Compose `restart: always` to pull updates and launch instantly.
* **Health Verification:** Waits up to 180 seconds post-restart to confirm the server is back online.
* **Logging:** Output is appended to a dedicated `.log` file for troubleshooting.

---

### Supply Drops (`supply_drop.sh`)
An automated event script that delivers weighted loot directly to active players. Designed to run as an hourly cron job.

* **RNG Loot Distribution:** Rolls a hidden number (1–1000) for every active user, followed by 3 secondary rolls matching item IDs in `pz-pool.txt`.
* **Custom Pool (`pz-pool.txt`):** Supports weighted loot tables generated by the server admin.
* **Durability Checks:** Evaluates the primary roll to apply item wear (e.g., rolls 950–1000 grant 100% durability; rolls 1–949 scale down to 50%).
* **Broadcast Options:** Configurable `servermsg` alerts. Can anonymously announce incoming drops or broadcast specific player rewards to drive PvP engagement.
* **Cooldown Engine:** Supports hourly rate-limiting, daily caps, custom interval locks, or manual execution overrides.

---

### GenMods (`genmods.sh`)
Automates the formatting of the `Mods=` entry inside `server_options.ini` by mapping installed Workshop IDs directly to their internal mod names.

1. Start the server and wait for all Steam Workshop downloads to complete.
2. Run `genmods.sh` and copy the generated `Mods=` string from the terminal.
3. Stop the server completely.
4. Update `server_options.ini` with the new string and restart.

## Utility & Edge-Case Scripts

A collection of helper scripts designed for server deployment, file system corrections, and targeted mod troubleshooting.

| Script | Purpose | Execution State |
| :--- | :--- | :--- |
| **CaseLinks** | Scans mod folders for casing inconsistencies (uppercase vs. lowercase) and standardizes path names to fix Linux loading errors. | **Offline Only** |
| **Refetch** | Targeted mod repair. Deletes specific Workshop mod directories and updates the server manifest to force re-downloading single mods without clearing the entire workshop cache. | **Offline Only** |
| **Deploy** | Deployment helper script designed to run alongside `Refetch` for environment synchronization. | **Offline / Setup** |

## Prerequisites

* Linux host environment
* Docker & Docker Compose setup using the [Indifferent Broccoli image](https://github.com/indifferentbroccoli/projectzomboid-server-docker)
* RCON enabled on the target Project Zomboid instance
* `cron` utility enabled on the host OS
